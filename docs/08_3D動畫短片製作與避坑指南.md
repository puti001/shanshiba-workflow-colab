## 二、製作新片的標準 SOP 與防坑檢查表

### 階段 1：劇本、首尾幀與 `film.json` 編寫注意事項
1. **先看圖再寫字**：
   - 任何一鏡的 `scene` 與 `action` 動筆前，必須先看過 `first/Sxx.png` 與 `last/Sxx.png`。
   - 嚴禁在文字裡描寫圖片上沒有的道具、人物或變形過程（圖文不符是 H3 中間幀融化崩潰的第一主因）。
2. **角色多型態拆分規則**：
   - 只要角色在片中有「變形」、「換裝」或「巨大化」（例如機器人變卡車、一般人變身裝甲），**必須在 `chars` 裡定義兩個不同的 key**，分別綁定對應型態的參考圖與外觀描述，絕不可共用同一個 `@char_id`。
3. **何時用 `use_last: true`、何時用 `use_last: false`**：
   - ✅ **適合 `use_last: true`**：跨空間位移、變形過程（`S02` 人變車、`S07` 亮盾牌）、物體碎裂消失（`S13` 大黑瓦解成晴空）。
   - ❌ **禁止 `use_last: true`**：
     - 首尾幀是同一張圖（`S01`）→ 設 `true` 必變靜態照片。
     - 首尾幀背景有多名學生／路人且姿勢相似（`S03`）→ 設 `true` 會導致背景人物全部結冰。

### 階段 2：雲端渲染前強制執行 Pre-flight Linter
把任務送上 Colab G4 燒算力之前，**必須先在本機跑過兩道零成本檢查**：
```powershell
python pipeline/<片名>/lint_v3.py
python pipeline/<片名>/build_specs_v3.py
```
確認：
- [ ] 全片 `style`、`scene`、`action` 無任何畫風衝突字眼。
- [ ] 沒有任何一鏡在 `first == last` 時誤開 `use_last: true`。
- [ ] `h3_shot.py --dry-run` 全數通過（`0 errors, 0 warnings`）。
- [ ] 所有鏡頭皆為 `"draft": false, "steps": 14`。

### 階段 3：Colab G4 渲染與算力保護
```powershell
python cloud/colab_h3.py check
python cloud/colab_h3.py start --h3-only
python cloud/colab_h3.py batch pipeline/<片名>/out/h3/S01/spec.json ...
python cloud/colab_h3.py stop   # ⚠️ 跑完立刻關機，否則每小時扣 8.9 運算單元！
```

### 階段 4：8 格密集抽幀與逐字時間戳後製 (`fix_v3_cut.py`)
1. **抽 8 格動態表決定剪輯點 (`TIGHT_TRIM`)**：
   - 不要只抽首尾格！每鏡均勻抽 8 格（`0% ~ 98%`），找出：
     - `cin`：跳過開頭多餘等待或異常前景物（如 `S06` 從 `2.5s` 切入、避開前 2.4 秒的大便當盒）。
     - `cout`：在角色動作與台詞剛結束、動能最強的那一格切掉（砍掉最後 1.5 秒的原地發呆或半空懸停）。
2. **用 `word_timestamps=True` 抽取完整台詞音軌**：
   - 切勿直接相信 Whisper 的 segment `end`！務必展開每個 segment 的 `words` 清單，拿第一個 word 的 `start - 0.12s` 與最後一個 word 的 `end + 0.18s` 切音檔，才不會把後半句台詞切掉。
3. **SFX 峰值正規化與 BGM Ducking**：
   - 無台詞鏡頭的環境／動作音效（`amb`）峰值正規化至 `0.58`，有台詞鏡頭正規化至 `0.35`，確保每一鏡都有紮實的聲音表現。
   - 台詞期間 BGM 自動壓低至 `22%`，整片透過 `ebur128` 校準至 `-15.5 LUFS`。
