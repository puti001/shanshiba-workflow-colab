# 03 規則與踩坑

每條規則都來自一次實際退件或實測。理由寫在後面，改規則前先看理由。

## 1. 劇本

| 規則 | 理由 |
|---|---|
| 16:9、24fps、每支獨立成篇 | 頻道規格；24fps 也是將來訓 LoRA 的前提 |
| 開寫前先問齊人物、場景、走向、風格、禁則 | 最大的浪費是批次生成完才發現共通缺陷 |
| 先給 2–3 個敘事方向再寫 | 一次驗收合格的片都是這樣開始 |
| 寫看得見的行動；反轉要能從前文線索回看成立 | 不要用解說對白代替戲 |
| 技術限制就是寫作限制：避開快打、追逐，一鏡一人說話 | H3 多人對話容易配錯嘴，快動作會崩 |
| 喜劇用「神話層 × 真相層」，靠切鏡製造反差 | 只靠旁白解釋笑點的版本被退件 |
| 校內角色不用手機；老師不碰學生（關心用表情、手放桌上） | 場域觀感 |
| 上課鏡背景一定有同學；角色不隨年級長大 | 退件項目 |
| 總結句用簡單常用字 | TTS 比較不會念錯 |

## 2. 空間與構圖

| 規則 | 理由 |
|---|---|
| 教室方位固定：黑板在前、學生面向黑板、窗在學生左手邊 | Image 2.5 自由構圖曾讓學生背對黑板 |
| 布置圖當 Image 2.5 參考，提示詞寫「只抄機位與站位，不抄方塊外觀」 | 鎖住空間 |
| 不同視角的首幀從**同一張底圖**編輯；首尾幀也從同一張圖改 | 換機位後背景會跑掉 |
| 不讓人物橫向走，改原地轉身 | H3 會跟拍，桌椅跟著滑 |
| 空景、時鐘、桌面特寫用靜圖＋慢推 | H3 會自己加人或切走 |
| 單人鏡提示詞完全不提其他人；多人鏡寫 `Exactly N people` | 提到誰誰就會冒出來 |
| 舞蹈等大動作的主角鏡：腰上或更近（臉佔畫高 10% 以上） | 768p 全景臉糊，放大救不回 |
| 一般遠景照拍；臉 < 50 px 的重要角色放大前跑 `tools/face_refine.py`（選用，2026-10-24） | 追臉後用 H3 低強度重畫臉、只貼回臉：25–30 px 的臉變得認得出本人；放大器（VSR、FlashVSR）救不回 |
| 提示詞必寫 `NO black letterbox bars` | 電影感提示詞會自帶黑邊 |

## 3. 角色一致性

| 規則 | 理由 |
|---|---|
| 每個角色一組：定妝照、轉面圖（正側背 3/4）、6 格表情表、**鎖定提示詞** | 每次照抄鎖定提示詞，不自己重寫外觀 |
| **本地生圖的參考圖只能是單張半身照**，不能用多格定妝表 | Qwen 會把多格版面照抄成拼貼 |
| 本地首幀不訓練時用 Qwen-Image-Edit 附參考圖；不要用 Qwen-Image 2.1 附參考圖 | 2.1 附參考圖會鎖死成參考圖的正面姿勢 |
| 生圖時以定妝照當 Image 2.5 參考圖 | 比 LoRA 簡單，效果夠 |
| 頭套寫「素色美洲獅、無條紋、無斑點、無鬃毛、布偶繡眼」 | 不寫會變老虎 |
| 頭套加「a lifeless prop whose sewn face and eyes never move」 | H3 會讓道具眨眼 |
| **多人鏡只給首幀**，不加 H3 身份參考圖 | 加了會多一個人 |
| 單人鏡才加身份參考，並寫明「只是外觀參考，不是要切過去的畫面」 | 否則 H3 會自己切鏡 |
| 低頭、轉身、再露臉 → Image 2.5 生尾幀鎖住 | 否則臉會換人 |
| 小孩要明顯是 11–12 歲（寫 childish face, never a teenager） | 第一版小雯像 16 歲 |

## 4. H3

| 規則 | 理由 |
|---|---|
| 一律用 `h3_shot.py`（官方 Ref2VA 六段格式＋格式檢查） | 規格一致；手寫容易漏段、標籤錯 |
| **`action` 寫 50–120 字**：「Starting from <Picture 1>, …」首幀定錨→動作開始→持續發展→結果，寫身體部位、幅度、次數，不寫抽象形容詞（官方 `h3-prompt-writing` 結構；2026-10-23） | 一句話版動作量只有 1/2.7，H3 照字面演，寫「誇張」它不知道多大 |
| 動作鏡首幀畫「動作開始前」的姿勢；彈跳等大動作首幀留頭頂空間 | 首幀已是動作最高點就只剩維持可演；跳太高頭出框、中段糊 |
| 預設只給首幀；長連續動作或一定要演到某個結果才加尾幀 | 對話與換場靠切鏡 |
| 尾幀機位構圖與首幀完全一樣，但**必須是不同的圖**（人要動時＝動作完成後的姿勢） | 構圖不同會搖鏡去對；同一張圖會把人鎖回原姿勢、畫面凍住（2026-10-23 再次實測：三種寫法都 100% 靜止）。只有人不用動、只鎖道具或螢幕字時才用同一張 |
| 沒鎖尾幀加「LOCKED-OFF STATIC CAMERA on a tripod」 | 否則鏡頭自己漂走 |
| `draft: true`（DMAD 4 步）是日常定稿；抽到就用，不要同 seed 改 14 步重生 | 8 類鏡頭並排看不出差、快 49–58% |
| 14 步留給：骨架舞蹈、群舞、細膩表情、Combat LoRA 拉滿 | 這幾類 DMAD 動量偏少或未驗證 |
| 特效「碎掉／消失」加 Image 2.5 尾幀 | 只給首幀 H3 不會做 |
| 定稿不開 EasyCache | 近景糊、靜止鏡出油畫雜訊 |
| 單鏡 ≤12 秒（約 294 格）；短插入鏡也至少生 5 秒再剪 | 15 秒會漂移、自己切鏡 |
| 不說話的臉給靜音引導音軌 | 否則會嘟囔 |
| 動作要「說到那個字的瞬間」發生（寫進提示詞） | 否則起立、敬禮慢半拍 |
| 長音：提示詞寫長音秒數＋「嘴維持張開到聲音結束」 | H3 會提早閉嘴 |
| 舞蹈、武打：一鏡到底＋**白模動作參考**（`make_whitemodel.py`，2026-10-14 起取代骨架控制；多人 `--colors`）＋首尾幀，最長 158 格 | 切片或用特寫避開都被退件；白模比骨架準（手臂形狀、踢腳、落地時間） |
| 動作 LoRA：Combat_V2 0.7、GunFu 0.9 | 實測有效；要保住首幀時避開 Motion_Repair 高強度 |
| H3 不要和別的 GPU 工作同時跑 | 搶顯存，慢約 10 倍 |
| 計時看 ComfyUI `/history` 的執行時間，不看牆鐘 | 佇列共用時牆鐘不準 |
| 不換成社群微調模型 Singularity V2（2026-10-24 A/B：6 鏡 × 2 seed＋動作鏡 14 步，同首幀同 spec 只換權重） | 動作大 1.5–2.4 倍、速度一樣，但①角色參考音念出來比較不像本人（雙人鏡 0.45–0.61 → 0.32–0.42）②推掌鏡 3／3 支把首幀後牆換成寫滿中文的黑板、1 支冒出旗子（構圖相關係數抓不到）③配角換臉、暖光變冷藍。要動作大，改 `action` 寫法就有 ×2.7 |
| SelfLift 兩段採樣（前段低解析、後段全解析）暫不用 | 只省時間不加畫質；DMAD 只有 4 步可省的少；直式前段只剩約 307×538；外掛沒有授權檔 |

## 5. 配音與發音

| 規則 | 理由 |
|---|---|
| **（2026-10-23 起預設）畫面內的台詞讓 H3 拿角色參考音自己念**：spec 寫 `"audio": {"voice_ref": {"subject": "<說話者>", "file": "ref_<角色>.wav"}}`；兩三人對話可同鏡：寫 `"voice_refs": [{"subject": ..., "file": ...}, ...]`（最多 3 位，各給參考音，每句台詞自動寫明用哪段音色） | 原頻道 RTX 5090 實測（同一場戲三鏡，對照 TTS 固定音軌、H3 無參考、雲端 Seedance 2.5）：像參考音 0.66（TTS 0.68）、三鏡一致性 0.75（最高）、表演比固定音軌生動、台詞全對。兩人同鏡（2026-10-23，2 seed）：第二位說話者像本人 0.10 → 0.45、聽寫與嘴型都對。本 repo 範本 2026-10-24 從頭實測：RTX 5090、7 鏡 6 句台詞 H3 全部念對、成片自審五遍通過、整支 27 分鐘 |
| H3 自己念的鏡頭**逐鏡聽寫比對原文**、同鏡抽 2 個 seed；抽 2–3 次都不對才改 BreezyVoice 固定音軌 | H3 會改成大陸用詞（「二十四號」→「二十四日」）、偶爾晚約 2 秒開口（剪接裁掉）；不能用注音逐字修 |
| BreezyVoice 固定音軌（`make_breezyvoice.cmd`）改當**備案**：念錯抽不出來、數字日期難字、要精準時間點的聲畫同步 | 2026-10-07 整片 53 句實測：台灣國語腔調分數 0.85，舊做法（Breeze／VoxCPM2）0.80；每句約 2.5 秒、顯存約 2GB。以下各條是 BreezyVoice 的做法 |
| （選用，原專案 2026-10-29 起的固定音軌預設）**Ming-3.0-TTS 0.5B**：`make_ming.cmd jobs.json`（格式同 BreezyVoice）。**一定要餵簡體字**（工具用 OpenCC `t2s` 自動轉，不要用 `tw2sp`，會換成大陸用詞）；Ming 會**太早收尾**（最後一個字被切、逗號後的短句不見）→ 句尾改「……」（工具補抽時自動改）；逗號後別放太短的句子；克隆模式不能加語氣指令，要表演用行內標籤 `[Sigh]`／`[Laughter]` | 原專案 2026-10-28 實測（三角色各 3 句、4 seed）：9 句全對、候選 31/36 合格（Breeze 12/35）、像參考音 0.86（Breeze 0.81）；餵繁體每支都念錯（線上報名→憲章奉明）；「…交到教務處。」4/4 句尾被切，改「……」3/3 完整。MIT 可營利 |
| 角色參考音定了就不要換（已公開的角色換聲音觀眾聽得出來） | 聲音是角色的一部分 |
| 參考音不要升調或變速處理 | 處理過的參考音會念不準 |
| 成品不用 Edge-TTS，它只當「標準台灣國語答案卷」 | 聲音不夠自然 |
| （VoxCPM2 備用時）繁轉簡再送 | 繁體字讀音較不穩 |
| 每句 8 個候選，`breezyvoice_pick.py` 自動挑：聽寫的**拼音＋聲調**要全對（同音字不算錯），有聲長度合理，再比台灣國語腔調分數 | ASR 只驗字，抓不到聲調；ASR 常把角色名寫成同音字 |
| 念不準的字**直接標注音**：`連假[:ㄐㄧㄚ4]`（標在字後面，聲調用數字），字幕用原文；常見的已內建在 `breezyvoice_batch.py` 的 `TW_BOPO` | BreezyVoice 支援注音標記，不必再找同音字（舊做法：掃→嫂、綜→縱） |
| 阿拉伯數字會自動轉國字；小數、英文縮寫請寫成國字 | Windows 版沒有文字正規化 |
| **單字台詞（例：「考。」「接！」）盡量改成兩三個字** | VoxCPM2 單字常念成亂音；BreezyVoice 的單字喊叫 ASR 會聽成別的字（「接」→「姐」），只能人耳判斷 |
| 聽寫（ASR）不對的候選一律不准選；抽 8 個都不對就改台詞 | 否則挑音程式會從一堆錯的裡挑一個 |
| 挑音的「標準台灣國語答案卷」用 edge-tts；沒網路才用 Breeze | 兩者挑出的第一名只有 4/19 句相同，原專案驗收過的是 edge-tts |
| 重要句最後請人聽一次 | 自動量測在小音量下不可靠 |
| 每幕檢查台詞時間軸有沒有重疊 | 旁白曾和廣播疊在一起 |

## 6. 音效與配樂

| 規則 | 理由 |
|---|---|
| 有動作、**而且看不到嘴**（背影、腳、手、遠景）的鏡頭，可以用 H3 原生音效（spec 不寫 `audio` 欄位） | H3 的腳步聲和畫面逐格同步 |
| **看得到臉的鏡頭一律不要讓 H3 自由出聲**：有台詞給角色參考音（H3 念該句）或備案配音，沒台詞給靜音固定音軌，就算有動作也一樣；需要動作音效時，另外用同一張首幀拍一支原生音效版，ASR 確認沒有人聲後只取它的音軌，或用音效庫 | 看得到臉時 H3 原生音效會讓角色自己嘟囔（2026-10-07 實測：翻書包鏡冒出「你去考古啊」） |
| H3 做不出的用 CC0 音效庫（repo 的 `sfx/`，58 個 Freesound CC0），不用程式合成腳步、肚子叫 | 合成的很假 |
| 配樂純器樂，`[Instrumental]` 約 14 個，分離後再用 | 會夾人聲、太短 |
| 台詞前後壓配樂 | 戰鬥配樂會蓋過台詞 |
| 停頓處墊很輕的房間聲；不要低頻隆隆聲 | 偏好 |
| 用了 MiniMax Music 3 要在片尾列名並註明 AI 生成 | 授權要求 |

## 7. 放大

| 規則 | 理由 |
|---|---|
| 近景、中景：768p＋RTX VSR ULTRA | 秒級、不改表演 |
| 全景、舞蹈：FlashVSR，逐鏡檢查多畫的細節 | 較銳，但會幻覺細節 |
| 不用 SeedVR2、SoL-Refiner | 會改臉、改嘴型、改時鐘 |
| 不用 VOSR2 逐格修臉（社群「H3 臉部修復」工作流的做法） | 是單張圖片超解析、不看前後格，跟 SeedVR2 同類風險；要修小臉用 `face_refine.py`（H3 重畫，有時間一致性） |
| 字幕不要先燒進低解析再放大 | 字會糊 |

## 8. 後製與剪接

| 規則 | 理由 |
|---|---|
| 畫面上的中文一律後製；考卷等「道具上的字」由 Image 2.5 直接畫再逐字核對 | H3 寫字會變亂碼 |
| 用 `ss` 裁掉開口前空白，不要拉長整鏡 | 尾巴會被切 |
| 同機位接續的對話鏡加 0.3 秒溶接 | 避免跳接 |
| 施法換場景要有魔法轉場（漩渦＋光點＋光環） | 不能只硬切背景 |
| 變臉用光流變形或 H3 首尾幀連續變化 | 遮罩擦過去看起來像剪接 |
| 遠景短、特寫多；動作定格後直接接反應鏡 | 節奏 |
| 審片附手機版 720p（<30MB） | 驗收的人在手機上看 |

## 9. 踩坑 Top 25

| # | 坑 | 對策 |
|---|---|---|
| 1 | EasyCache 讓近景糊、近乎靜止的無聲鏡出油畫雜訊 | 定稿不開快取 |
| 2 | 首尾幀用同一張圖 → 畫面幾乎凍住 | 尾幀必須是不同的圖 |
| 3 | 沒鎖尾幀，鏡頭自己搖走 | 三腳架固定句，檢查首尾格構圖 |
| 4 | 尾幀構圖和首幀不同 → H3 搖鏡去對 | 首尾幀從同一張圖編輯，只改動作 |
| 5 | 多人鏡加身份參考 → 多一個人 | 多人鏡只給首幀 |
| 6 | 附角色設定圖 → H3 一鏡內自己切鏡 | 寫明只是外觀參考 |
| 7 | 低頭或轉身後臉換人 | 尾幀鎖臉 |
| 8 | 提示詞提到其他人 → 空教室冒人、出現兩個老師 | 單人鏡不提旁人、`Exactly N people`、換 seed |
| 9 | 無台詞的臉自己嘟囔；多人鏡嘴型配到錯的人 | 靜音引導；說話者放前景最大 |
| 10 | 開口晚 1.4–2.8 秒 | `ss` 裁頭 |
| 11 | 長音提早閉嘴 | 提示詞寫長音秒數；用能量（−35 dB）量真正結束點 |
| 12 | 鏡頭露出黑板就寫亂碼字 | 尾幀鎖定、掃全部格、換 seed |
| 13 | 15 秒鏡頭漂移、自己切鏡 | ≤12 秒 |
| 14 | 三人正面踢腿幾乎每個 seed 都長第三條腿，縮圖看不出來 | 拆單人鏡；看原解析度高峰格 |
| 15 | 骨架時間軸不夠長，結尾被補成標準站姿 | 收尾段用最後一格填滿＋尾幀 |
| 16 | 靠提示詞指定哪隻腳，結果左右反了 | 骨架或尾幀鎖定 |
| 17 | 768p 全景臉糊 | 大動作主角腰上以上；一般遠景小臉用 `face_refine.py` 修 |
| 18 | ComfyUI SaveVideo 只有約 3 Mbps | 存 PNG 影格自己用 CRF 12 編碼（`h3_shot.py` 已處理） |
| 19 | 重拍時重用舊資料夾 → 結果一模一樣 | 每次新 attempt 資料夾、新 seed |
| 20 | 牆鐘計時含其他工作排隊 | 用 `/history` |
| 21 | 背景通知寫「完成」，工作其實沒送出 | 自己查 log、`/queue`、GPU |
| 22 | ASR 全對但聲調錯（港腔／大陸腔） | BreezyVoice＋`breezyvoice_pick.py`（腔調分數）＋注音標記＋人聽 |
| 23 | Image 2.5 安全系統擋 "despair" 之類措辭 | 換說法 |
| 24 | 首幀底部用邊緣複製補畫面 → H3 長成鞋底黑條 | 用 Image 2.5 重畫 |
| 25 | 先整片批次才發現共通缺陷（13 鏡累積 25 版） | 訪談 → 布置圖 → 最難一鏡先測 → 再批次 |
| 26 | 3D 動畫片的 `style` 誤留 `photorealistic live-action`，或在正向 prompt 寫 `no photorealistic` → 中間幀突變成真人臉與實拍建築 | `style` 與角色 `desc` 一律只寫純正向 3D 動畫描述（Pixar-like 3D CG cartoon），嚴禁出現任何 `photorealistic`/`live-action` 字眼（含否定句），送審前跑 `lint_v3.py` |
| 27 | 變形角色（如機器人變推土機）共用同一個 `@char_id` → 載具鏡中間幀自己長出人手人腳 | 不同型態必須拆成兩個獨立角色 ID（如 `xiaoji` 與 `xiaoji_truck`） |
| 28 | 多人互動鏡綁了背景人物姿勢相同的 `last_frame` → 主角在動、背景學生像蠟像結冰 | 背景有多人互動或 `first == last` 時，強制設 `use_last: false`，並在 `action` 寫明背景人物動作 |
| 29 | 用 Whisper 抓台詞結尾未開 `word_timestamps=True` → segment 結尾被量化在 4.15s/5.15s，後半句台詞被切掉（有嘴型無聲音） | 抽取 H3 台詞音軌必開 `word_timestamps=True`，取最後一個 word 的 `end + 0.18s` |
| 30 | 整條 6 秒 H3 原片不修剪直接串接 → 最後 1.5~2 秒角色做完動作原地乾等或懸停半空 | 先抽 8 格密集動態表標定 `TIGHT_TRIM`，在動作最高點切走（使用 `-vf trim=...,setpts=PTS-STARTPTS`） |
| 31 | `6.5s` 單鏡塞入 35~45 字台詞 → 語速飆到 6.6 字/秒像機關槍，H3 尾字念不完、後製又套 `atempo` 加速 | `6.5s` 鏡頭台詞嚴格限制 **≤ 25 個漢字**（正常人語速 4 字/秒）；若已算完圖需放慢，畫面 `stretch` 必須動態由 `(d_raw + 0.35) / raw_shot_len` 反推並關閉 `atempo` 加速上限 |
| 32 | 混用 H3 原生音軌與 VoxCPM2/TTS 補錄音軌，且對 H3 套 `lowpass=12000,afftdn` → 前後鏡聲音「忽亮忽悶」斷層明顯 | 移除 H3 音軌的 `lowpass` 與 `afftdn`，改加 `equalizer=f=3500:t=q:w=1.0:g=6.5,treble=g=8.5:f=6000` 提亮，使全片 `>3.5kHz` 頻譜能量統一在 `30%~50%` |
| 33 | 補錄 TTS 腳本手打草稿台詞，且 `review.py` 漏加 `--asr` → 成片出現「聲音跟字幕不同句」卻未被自審攔截 | 補錄腳本一律從 `film.json` 讀取 `shot["line"]["text"]`；後製結尾強制跑 Whisper ASR 與字幕逐句比對 |
| 34 | 多人同鏡時 `line.who` 填 A 角色，但畫面實際張嘴說話的是 B 角色（如 `S13` 黃老師開口卻配佛陀音） | Gate 2 檢視 8 格抽幀表時，必須確認畫面張嘴者與 `line.who` 一致；不一致時直接將字幕與配音改為開口角色 |
| 36 | 長句字幕單行超過 20 字貼邊、或用 \\N 一次塞兩行遮擋畫面 | 依標點拆成多段依序顯示的**單行字幕**（split_sub_clauses，每行含角色名嚴格 **≤ 20 字**，一次只出現 1 行，依字數比例分配時間軸） |
| 35 | FFmpeg 音軌放慢時把 `-to` 放在 `-i` 後面（`-i clip.mp4 -to 6.44 -af atempo=0.86`）→ 放慢後的音軌在 6.44s 被硬切掉尾端 | 裁切與變速同跑時，一律在 `-af` 內用 `atrim=start=...:end=...,asetpts=PTS-STARTPTS,atempo=...` |

> 完整 V1→V2→V3 診斷與修復範例請見 [08_3D動畫短片製作與避坑指南.md](08_3D動畫短片製作與避坑指南.md) 與 [09_2D動畫短片與文化導覽實戰復盤_菩提心起.md](09_2D動畫短片與文化導覽實戰復盤_菩提心起.md)。

## Windows 小坑

- ffmpeg 9 不支援 `-filter_complex_script`，改 `-/filter_complex`。
- drawtext 字型路徑的冒號要跳脫：`C\\:/Windows/Fonts/...`。
- faster-whisper 缺 cuBLAS DLL：把 venv 裡 `nvidia/*/bin` 加進 DLL 路徑（`stt.py` 的 `_add_cuda_dll_dirs()`）。
- 標楷體用 `kaiu.ttf`；`mingliub.ttc` 是 ExtB 字集，一般字會變方塊。

### 踩坑 37：9:16 滿版智慧導播運鏡盲猜座標，導致人物臉部切半（S01 0–6s 切臉事故）
- **現象**：在 9:16 滿版裁切（16:9 寬 1920 僅取寬 607.5px 視窗）時，未看畫面直接憑印象寫 cx=0.23，導致站在 x=640px (cx=0.33) 的主角整整 6 秒臉被切一半。
- **解法**：嚴禁盲猜座標！所有 9:16 導播運鏡成片交付前，**必須執行 [inspect_vert.py](../pipeline/puti_xinqi/inspect_vert.py)** 抽取全部 14 幕的 15%, 50%, 85% 共 42 張關鍵影格拼成 ert_panscan_check.jpg 逐格肉眼審查。

### 踩坑 38：9:16 單顆 7.5 秒鏡頭塞入 3 個停留點（Hold-Pan-Hold），導致搖鏡過快突兀
- **現象**：在 7.5 秒鏡頭內設定「左角色停留 → 搖至中景文物停留 → 搖至右角色停留」3 個錨點，扣除頭尾與中間停留時間後，每次橫搖跨越 35% 畫布僅剩  .85~0.95 秒（約 22 格移動 600px），視覺上產生急促甩鏡（Whip-pan）突兀感。
- **解法（雙焦點慢搖或虛擬導播切鏡鐵律）**：
  1. **單鏡最多 2 個焦點（1 次慢速搖鏡）**：7 秒鏡頭內最多只做一次平緩移動（移動時間 >= 2.2 秒），或直接單人定鏡（Hold）。
  2. **跨場域改用「虛擬雙機切鏡（Virtual Multi-cam Cut）」**：當需要從畫面最左側（cx=0.16）跳到最右側（cx=0.80）的對話者時，不要硬滑過中間空白背景，直接配合分句字幕切換時間點（Clause Cut）做 0 秒硬切（Hard Cut），完全符合真人導播切換雙機位特寫的自然視覺習慣。
