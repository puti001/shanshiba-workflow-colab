# 09 2D 動畫短片與文化導覽實戰復盤（以《菩提心起：佛陀教我做導覽》為例）

本文件整理《菩提心起：佛陀教我做導覽》（14 鏡、2D 賽璐珞手繪風格、佛陀紀念館文物導覽題材）從早上開案到成片交付過程中所採用的**新技術方案、7 大實戰踩坑、根因剖析、解決方案與下一支片的前置防呆建議**。

---

## 一、 本次採用的新技術與工作流升級

### 1. PDF 展品知識庫與真實視覺錨點自動萃取
* **做法**：利用 PyMuPDF (`fitz`) 直接從策展手冊（`展品資料.pdf`）與現場場勘（`展場影片截圖.pdf`）自動抽取出 29 張高清文物圖與 23 張展廳實景圖，建立文物結構描述表（如黃土水〈釋迦出山〉蓄鬍赤足、北齊〈張解造像碑〉碑底供養人、宋代〈泥塑加彩羅漢〉深邃眼窩與微蹙眉頭）。
* **效益**：生圖 Prompt 不再憑空想像佛像外觀，而是 100% 錨定真實館藏文物特徵。

### 2. 「單張滿版 16:9 原生構圖 ＋ 同對話串接續編輯（In-Thread Edit）」取代雙聯畫分割
* **痛點**：傳統「左右雙聯圖（2-panel side-by-side）」塞進一張橫圖時，單格比例會被迫變成接近正方形，切回 `16:9` 時上下會被裁掉 40%，或導致雙人＋中間展櫃放不下。
* **新做法**：
  * **單幀鏡（6 鏡：`S01, S03, S05, S09, S11, S12`）**：直接生單張滿版 `16:9` 首幀，`use_last: false`，靠 H3 的 `action` 與 `LOCKED-OFF STATIC CAMERA` 演繹自然動作。
  * **首尾鎖定鏡（8 鏡：`S02, S04, S06, S07, S08, S10, S13, S14`）**：先生成滿版 `16:9` 首幀，再於**同一個生圖對話串**下達「保留 100% 相同展廳背景與機位，只改角色動作成尾幀」的接續指令。
* **實測成果**：背景鎖定率 100%，完全消除雙聯圖比例裁切與左右格光影不一致的問題。

### 3. 一魚兩吃：16:9 母帶 ➔ 9:16 博物館級手機直式版（零裁切）
* **痛點**：展場空間寬廣適合 `16:9`（左黃老師、中展櫃、右佛陀／遊客），但現代觀眾習慣用手機直式看 Reels / Shorts；若直接從 `16:9` 正中央裁切 `9:16`，左右兩側的黃老師與佛陀會被整個人切掉。
* **新做法**：以 FFmpeg 複合濾鏡將 `16:9` 母帶滿幅縮放至 `1080×608` 居中鑲嵌於黃金畫框，底層鋪設同畫面動態高斯模糊（`boxblur=28:4,eq=brightness=-0.38`），上方固定疊加特展雙行大標題，下方配置雙行大字號字幕與版權宣告。

### 4. 自動標點智慧雙行字幕（Smart 2-Line ASS Wrapping）
* **做法**：針對超過 23 字（`16:9`）或 17 字（`9:16`）的台詞，自動搜尋句中離中點最近的標點符號（`，。？！、：…`）插入 `\N` 強制折為上下兩行，並設定左右安全邊距 `MarginL/R = 110`。
* **效益**：徹底解決單行長句（35～42 字）貼齊畫面左右邊緣甚至超出畫框的問題。

## 二、 7 大踩坑經驗與問題解決對照表

| # | 踩坑現象 | 根本原因（Root Cause） | 解決方案（Solution） |
| :--- | :--- | :--- | :--- |
| **坑 1** | **語速過快像趕火車**（每秒高達 6.5 字，且 `22~44s` 明顯偏快） | 1. **分鏡台詞字數超載**：H3 單鏡硬上限為 `6.5s`（157 格），正常導覽語速為 `4～4.5 字/秒`（單鏡上限應為 **24～26 字**），但劇本每鏡塞了 **35～44 字**（如 `S04` 達 46 字、`S11` 達 41 字）。<br>2. **後製防切字強制加速**：`fix_v3_cut.py` 為防止台詞超過鏡長被 `Pass 5` 判定切尾字，當 `d_raw > max_allowed` 時自動套用 `atempo=1.25~1.38` 將音檔硬壓回鏡內（如 `S04~S06` 雖用 `-4%` 語速重生成 `7.8s`，但因鏡長設 `7.5s`，又被 `if d_raw > max_allowed` 自動加速壓回）。 | 1. **治本**：`lint_v3.py` 新增單鏡字數硬上限檢查（`6.5s` 鏡頭台詞嚴禁超過 **26 字**）。<br>2. **後製治標**：若已算完圖，鏡頭延展倍率 `stretch` 必須動態由音檔原長反推：`stretch = max(1.0, (d_raw + 0.35) / raw_shot_len)`，而非寫死固定 `1.16x`，才能完全不觸發 `atempo` 加速。 |
| **坑 2** | **有些幕聲音亮麗立體，有些幕聲音悶扁**（前後切換像不同人） | 1. 混用了兩種頻寬截然不同的音源：修復鏡（`VoxCPM2`）為 `44.1kHz` 全頻段純淨人聲（`>3.5kHz` 高頻能量佔 `45%~54%`）；而未修復鏡使用 H3 原生音軌（`>3.5kHz` 僅佔 `6%~7%`）。<br>2. `fix_v3_cut.py` 原本對 H3 音軌套了 `lowpass=f=12000,afftdn=nf=-20`，把高頻空氣感進一步削平。 | 1. 移除 H3 原生音軌的 `lowpass` 與 `afftdn`。<br>2. 對 H3 原生音軌加上高頻清晰度與空氣感補償：`equalizer=f=3500:t=q:w=1.0:g=6.5,treble=g=8.5:f=6000,acompressor`，使 H3 原聲 `>3.5kHz` 能量拉齊至 `35%~49%`。 |
| **坑 3** | **外掛 TTS 覆蓋後「字幕跟聲音不同句、嘴型也合不來」** | 1. 手動重寫 TTS 修補腳本時，直接手打初版草稿文字，未從 `film.json` 動態讀取 `shot["line"]["text"]`，導致 `S02, S03, S06, S08, S09` 念出舊版台詞。<br>2. H3 已經把畫面嘴型鎖定在它自己的原生音軌時間軸上，若把原本咬字清楚的 H3 原聲全換成外掛 TTS，停頓點不同就會嘴型脫節。 | 1. **鐵律**：任何配音修復腳本**嚴禁手寫台詞字串**，一律 `json.loads(Path("film.json").read_text())` 讀取 `s["line"]["text"]`。<br>2. H3 原生咬字清楚的鏡頭（`S02, S03, S08, S09, S12, S14`）一律保留 H3 原聲對嘴＋EQ 提亮，只針對漏字／糊字的鏡頭做局部修復。 |
| **坑 4** | **`review.py` 五遍自審沒抓出「語音跟字幕不同句」** | `fix_v3_cut.py` 呼叫 `review.py out/cut/film_1080p.mp4` 時**漏傳 `--asr` 參數**，導致第 2 遍（成片 Whisper ASR 逐句比對字幕）被跳過，只檢查了畫面與 LUFS 響度。 | 在 `fix_v3_cut.py` 與自審流程中，強制將 Whisper 實聽文字與 `film.json` 字幕逐句列印比對（相似度 `< 0.75` 直接報錯攔截）。 |
| **坑 5** | **`01:14` (`S13`) 畫面是黃老師嘴巴在動，但配成佛陀聲音與佛陀字幕** | 多人同鏡（`["buddha", "huang", "visitors"]`）時，`film.json` 的 `line.who` 誤填為 `"buddha"`，但首尾幀與 `action` 實際開口說話的是左方的黃老師。 | 多人同鏡在 Gate 2 檢視 8 格動態表時，必須核對**「畫面上誰的嘴巴在張合」**與 `line.who` 是否一致；不一致時直接將 `line.who` 與配音改為實際開口的角色（免重算影片）。 |
| **坑 6** | **FFmpeg `-to` 放在 `-i` 後面導致 `atempo` 放慢後的音軌被截斷** | 執行 `ffmpeg -i clip.mp4 -ss 0 -to 6.44 -af atempo=0.86` 時，`-to 6.44` 限制的是**輸出檔**長度（把放慢後應為 `7.47s` 的音檔在 `6.44s` 處硬切掉最後 1 秒）。 | 時間裁切與變速同跑時，一律在 `-af` 內部寫 `atrim=start=...:end=...,asetpts=PTS-STARTPTS,atempo=...`，絕不在輸出端加 `-to`。 |
| **坑 7** | **VoxCPM2 使用短版 `prompt_wav_path` 發生參考音外溢（Prompt Bleed）** | 為了加速 CPU 推理，將 `prompt_wav_path` 截短至 `4.95s`，結果生成的音檔前 `4.8s` 先把參考音後半句複誦了一遍才開始念目標台詞。 | 使用 VoxCPM2 零樣本克隆時，直接傳入 `reference_wav_path=ref_wav`（不傳截斷的 `prompt_wav_path`），或生成後務必用 Whisper `word_timestamps=True` 定位目標台詞首字起點。 |

## 三、 給下一支片的 5 條黃金防呆建議（省時、省額度、一次過關）

1. **【Gate 1 鐵律】6.5 秒鏡頭台詞嚴禁超過 25 個中文字**
   * 在寫 `build_film_v3.py` 階段，由 `lint_v3.py` 強制檢查：`len(clean_text) <= 25`（每秒 `3.8～4.2` 字）。
   * 這一條能同時解決**「語速過快」、「H3 尾字念不完被切」、「後製被迫套 `atempo` 加速」**三大問題，從源頭根除！
2. **【省 Token 鐵律】本機 CPU 跑 VoxCPM2 一次載入模型批次生完，不在對話迴圈裡單句重跑**
   * 本機無獨顯（CPU 模式）跑 VoxCPM2 每句需 60～90 秒，若分 3 次背景任務呼叫會消耗大量等待輪次與 Agent 額度。
   * 應在 Gate 2 跑完一次 Whisper `word_timestamps` 後，列出所有需補錄的鏡號，寫成**單一批次腳本（只載入一次模型）**一次跑完。
3. **【對嘴鐵律】生圖與 `action` 明確指定唯一開口角色：`Only [Character] speaks; others nod with closed mouths`**
   * 多人同鏡時，務必在 `action` 寫明誰開口說話、誰閉嘴點頭微笑，並確保 `line.who` 與畫面開口者 100% 對應。
4. **【音質統一鐵律】H3 原聲與補錄 TTS 必須過同一個「頻譜明亮度正規化（Spectral Matching）」**
   * 混音前自動計算每句 `>3.5kHz` 頻譜能量佔比，若 H3 原聲低於 `25%`，自動掛載 `equalizer=f=3500:g=6.5,treble=g=8.5:f=6000` 提亮，禁止直接套 `lowpass` 或重度 `afftdn`。
5. **【自審鐵律】`fix_v3_cut.py` 結尾強制輸出「12 鏡字幕 vs Whisper 實聽對照表」**
   * 任何一次合成或修改音軌後，腳本必須自動跑完 Whisper 轉寫並比對 `film.json` 字幕，不再依賴肉眼猜測或漏加 `--asr`。
